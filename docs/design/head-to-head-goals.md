# PixelDarts Chess head-to-head refactor

This is the durable handoff for the refactor. Run each numbered section as one
`/goal`, in order, and do not mark it complete until its evidence is present in
the current checkout.

## Product invariants

- Replace `games/pixeldarts_chess_128_160` in place. Keep its folder and
  `conf.json` id.
- The playfield is 128x128 plus the existing 128x32 status strip.
- A round uses a seeded 3x3 grid: eight unique values from 1 through 20 and a
  25-point center bull. Normal targets are 35px; the bull is 19px.
- Both colors play the same grid. A hit removes a cell. Misses, removed cells,
  duplicate hits, and the strip (`y >= 128`) score zero. Three darts per color.
- The chase player sees `BEAT` and `NEED`, with no suggested target.
- Alternate the first shooter by chess color each ranked round.
- Ties use one-dart sudden death on a new seed shared by both colors. Repeat on
  another tie. Never select random chess because of a tied dart score.
- `maximum_possible_score` is the sum of the three highest cells on that grid,
  including 25. There are no bombs or balloons.
- The chess position persists between rounds. Each win buys up to six
  sequential plies from `docs/continuation-planner.md`, never a beam search.
- Rounds 1 through 3 suppress mating candidates unless all returned candidates
  mate. After round 3 animation, show `CHECKMATE UNLOCKED`; round 4 permits mate.
- Minigame code never imports chess. Continuation code never receives dart hits
  or raw scores. `Match` alone maps `RoundResult` to `ContinuationRequest`.
- Keep `main.py`, `frame_pump.py`, `input_adapter.py`, piece sprites, and the
  selected Kenney target assets. Remove opening bands, dartboard wedges, and the
  old coordinator as the replacement lands.
- Do not upload to a physical board or open a pull request unless requested.

## Environment split

Goals 0 through 4 run without a Stockfish process. Tests unset
`STOCKFISH_API_URL`, inject fixture-backed analysers, and never contact the LAN.
Goal 5 runs on a worker that can reach the evaluator currently documented as
`http://192.168.1.43:8096`. Runtime Compose configuration is owned by
`feocco/homelab-config`.

The repository removes `POST /rank` as soon as callers migrate to
`POST /analyse`. There is no compatibility endpoint. Goal 5 separately proves
that the running homelab container no longer exposes `/rank`.

## Offline fixture contract

Goal 2 creates:

- `tests/fixtures/analyse/manifest.json`
- `tests/fixtures/analyse/*.json`, one `/analyse` response per scenario
- `tests/fixtures/continuation/`, containing sequential response scripts and
  frozen continuations for rendering

An analyse response has this shape:

```json
{
  "fen": "a full FEN",
  "multipv": 8,
  "root_score_cp": 31,
  "white_expectation": 0.53,
  "pvs": [
    {
      "multipv": 1,
      "uci": "e2e4",
      "san": "e4",
      "score_cp_stm": 38,
      "mate": null
    }
  ]
}
```

Every UCI must be legal in its fixture FEN. Fixtures are authored to force
policy branches; they are not generated by Stockfish and do not claim to
represent Stockfish's preferred move.

The manifest must list fixtures for:

- white-to-move and black-to-move MultiPV parsing
- exact 0, 40, 100, 200, and 350cp loss targets
- nearest-loss selection and the all-under largest-loss fallback
- early-round PV1 mate filtering, all-candidates-mate fallback, and round-4 mate
- fewer than eight rows, one illegal UCI mixed with legal rows, stalemate, and
  checkmate
- a legal six-ply script, a shorter terminal script, a canned six-ply
  continuation, a canned terminal continuation, and a canned round-4 mate

Tests load these files through one shared `FakeAnalyser`. Inline response dicts
may be used only for malformed HTTP input tests, not planner behavior.
